# ContinuousSR：连续表示与快速渲染要一起看

本地保存的是2025-03-09 **arXiv v1技术报告**，18页，包含补充内容。正式发表身份为ICLR 2026，但本地附件不能冒称最终会议稿。OpenReview下载遇到验证，采用可公开访问的原版本；版本信息见 [LIIF路线检索记录](../../PUBLICATION_SCOPE.md)，附件与作者见 [ContinuousSR](ContinuousSR.md)。本页是原创导读，未交付全文译本。

## 先抓住效率问题

输出图片越来越大时，算法要生成的像素越来越多。如果连续表示中的一部分计算可以复用，且渲染实现足够并行，就可能减少重复计算。但这需要区分编码一次的成本与针对输出网格渲染的成本。

该技术报告围绕显式二维高斯表示与快速连续超分辨率，讨论Deep Gaussian Prior和Adaptive Position Drifting。学习时关注高斯如何产生、位置怎样调整、像素如何光栅化；作者的速度数字须绑定设备和尺寸，不能当成任意图片的承诺。[arXiv版本](https://arxiv.org/abs/2503.06617v1)

## 原创例题：固定开销与变化开销

假设一个教学系统编码耗时4ms，小尺寸渲染耗时1ms，大尺寸渲染耗时3ms。端到端耗时分别是多少？如果只报渲染速度会给读者什么不同印象？

**解答。** 总时间分别5ms和7ms；只报渲染会看到1ms和3ms。两种口径都可以用于回答特定问题，但必须说明计时范围。如果一次编码后渲染多个尺寸，复用条件也需要写明。这些数字是算例，不是该论文实测。

## 原创例题：平均速度并不告诉你最坏情况

三个样本延迟为[1,1,10]ms，平均为4ms，中位数为1ms。报告其中任何一个数字都不能完整描述尾部延迟。图像内容若改变高斯覆盖与调度负担，应额外检查波动，而不是只看均值。

## 与两篇高斯工作放在一起读

- [GaussianSR](../05_GaussianSR_2025/GaussianSR.md)：先明确连续表示位于特征空间还是最终颜色空间。
- [GSASR](../06_GSASR_2025/GSASR.md)：对照可泛化高斯预测与光栅化实现。
- [QuADA-GS](../08_QuADA-GS_2026/QuADA-GS.md)：进一步问每个区域分配多少高斯，以及稀疏结构是否带来额外管理开销。

这些是问题导向的对照，不把三篇并列方法写成未经证实的直接继承链。

## 怎样使用附录和代码

查模型细节、训练条件和更多视觉结果时，注明所在版本。官方仓库对公开代码与原始实现的说明也应保留；能够运行一个公开版本不等于完整复现原始训练。当前项目没有运行任何模型，因此所有论文性能都标为作者报告。

## 文末：术语与前置知识

| 术语 | 中文解释 |
|---|---|
| explicit representation | 显式表示：用可直接操作的一组参数/基元表达信号 |
| Gaussian prior | 高斯相关先验；具体网络和约束见原文，不能把“prior”只解释成概率分布 |
| position drifting | 位置调整；关注它的输入、幅度约束与训练方式 |
| rasterization | 把连续基元贡献写到离散像素，见 [高斯泼溅与光栅化](../../02_%E6%A6%82%E5%BF%B5/%E9%AB%98%E6%96%AF%E6%B3%BC%E6%BA%85%E4%B8%8E%E5%85%89%E6%A0%85%E5%8C%96.md) |
| latency / throughput | 单次耗时与单位时间处理数量，二者不总是成反比 |
